# テストシナリオ 1 — FW ポリシ反映漏れによる LB ヘルスチェック失敗

トポロジー解析タブを動かすためのサンプル一式。LLM が `suspected_node_ids` に
正しく `fw-01` と `lb-01` を出してくれるかを目視確認するのが目的。

## 構成

```
Internet → fw-01 (FW) → lb-01 (LB) → app-01 / app-02 (Server) → db-01 (DB)
```

## 障害ストーリ（実装側のシナリオ — 学習や確認用）

- 09:00 直前に fw-01 のポリシをリロード（rev `2026-05-25_001`）
- 新ポリシから誤って **`lb-to-app-01` ルールが抜けた**
- LB → `app-02` は permit、**LB → `app-01` は default-deny で落ちる**
- LB のヘルスチェック (`10.0.1.10 → 10.0.2.11:8080`) が連続失敗 → `app-01` が DOWN とマーク
- app-01 自体はプロセス健全。「**インバウンド接続が 0**」というシグナルがログに残る
- app-02 は単独で全量を処理 → レイテンシ上昇

## 期待される解析結果

| 項目 | 期待値 |
|---|---|
| `suspected_node_ids` | `["fw-01", "lb-01"]`（`app-01` も含まれる場合あり） |
| root_cause rank=1 | FW カテゴリ：`lb-to-app-01` ルールが新ポリシから欠落 |
| recommended_actions | 「ポリシ rev を `2026-05-24_007` にロールバック」など。`human_judgment_required=true` |
| confidence | 0.85 前後（複数監視が一致 + トポロジ裏付けあり） |

## 操作手順

1. UI で **トポロジー解析** タブを開く
2. 「画像を選択」で `diagram.svg` をアップロード
3. 「ノード追加（ドラッグで矩形描画）」モードに切替、5 ノード分の矩形を画像上の各ボックスに重ねて描画
4. 各矩形を選択しサイドパネルで:
    - id を `fw-01` / `lb-01` / `app-01` / `app-02` / `db-01` に変更
    - type を `FW` / `LB` / `Server` / `Server` / `DB` に
    - ip を `10.0.0.1` / `10.0.1.10` / `10.0.2.11` / `10.0.2.12` / `10.0.3.20` に
    - 「samples/logs/ から読み込み」で `scenario1_<id>.log` を読み込む
5. 「トポロジー解析を実行」
6. 完了後、`fw-01` と `lb-01` の矩形が赤系で点滅ハイライトされるはず
